## Incident: "error after submitting a question / question not in the staff question bank"

### Root cause (with evidence)

1. **React hooks-order crash in `AskView` (primary — the error students saw).** The rotating-placeholder `useState(() => pickAskExample())`, added in the 2026-10-30 copy pass, sat *after* `if (done) return …`. The first render after a successful send calls one hook fewer, and React throws "Rendered fewer hooks than expected". The view fell into the error boundary with no ticket shown. The question *was* saved, but a student who re-sent from the remounted form created a duplicate with a new ticket.
   - Deployed bundle (Oct 31 build, `dist/assets/index-B6mTyCKT.js`): `…Ask another question"})]});const J=!o,[B]=b.useState(()=>MA());return …`, a hook after the success-screen return.
   - Reproduced: `node scripts/e2e/ask-render-check.mjs --simulate-hooks-bug` FAILS with "Rendered fewer hooks than expected … (questions on the server: 1)". The fixed tree passes 6/6. The new bundle reads `…Ask another question"})]});const G=!l;return …`, with no hook after the return.
2. **Silent browser-only "save" (why some questions never reached the bank).** `hasApi()` cached a failed `ping` for the rest of the visit. Deployed code: `if(sr!=null)return sr; … catch{sr=!1}`. After one cold start or Wi-Fi blip, the Ask submit fell back to `localStorage`, showed success, and nothing reached the server. Those questions exist only in those visitors' browsers and can't be recovered server-side.
3. **Server hardening (not seen failing, but could fail a submit).** The post-submit AI enqueue wasn't wrapped, and the 1.5 s timeout race could leave a late rejection unhandled. Ruled out:
   - New stage and country values were never rejected (no server allow-list existed).
   - Firestore writes already strip `undefined`.
   - CSP is same-origin.
   - Triage runs in the background worker, not in the submit.
   - No email is sent at submit time.
   - Source counting is a separate fire-and-forget `visitSource` op.

### Fixes

- `src/App.jsx`:
  - All `AskView` hooks now run before any early return.
  - The dropdowns come from the shared lists.
  - On a built site, the Ask submit always goes to the API (no localStorage fallback).
  - A failed ping is retried after 8 s.
  - One automatic resend on a network error or 502/503/504, reusing the same id and ticket, so the server treats it as an idempotent duplicate.
  - `api()` tags network and timeout errors.
- `src/askSubmitError.js`: specific messages for offline, timeout, 429 and server errors. Every one says "Your question is still here", and the typed question stays in the form.
- `shared/askOptions.js` (shared by client and server):
  - `ASK_STAGES` includes "Ayurveda student (other course)", "Researcher" and "Changing careers"; `ASK_STATES` includes "Outside India".
  - `normalizeAskRecord`: strings only, capped lengths, no `undefined`, no staff-only fields.
  - `askRecordProblem`.
  - `offListAskFields`: off-list values are logged and kept, never rejected.
- `server/storePlugin.js`: a student's submit is normalised to Ask fields at the id its key names. Errors are specific 400/500 messages (no bare "store failed"). The AI enqueue and worker kick are in a try/catch, and the response carries `ticket`.
- `server/ai/ops.js`: the catch is attached before the timeout race (no unhandled rejection), plus a `setEnqueueForTests` seam.
- `shared/ticket.js` + Track: ticket lookup tolerates case, spaces, autocorrected dashes, a leading `#` and a missing `AYM-Q-` prefix (added by the concurrent agent).

## Remaining risks / follow-ups

- **Production is unverified until the parent deploys and runs the probe.** The sandbox blocks outbound HTTPS.
- **Lost questions:** questions "saved" to localStorage during the incident never reached the server and can't be recovered. Consider a short notice asking anyone who asked before the fix to check Track and re-ask if their ticket isn't found.
- **Duplicates:** students who re-sent after the crash may have two tickets for one question. Curation's auto/suggested merge should group them; staff should glance at recent near-identical questions.
- **New staff-only surface:** `testProbeSession` / `testProbePurge` (`server/testProbe.js`) are PIN-gated and limited to `aym-probe+…@ayurdisha-qa.test` emails and "[TEST]" questions. Keep them; they are what lets the probe clean up.
- **happy-dom isn't a project dependency.** The render checks print SKIP when it's missing (`npm install --no-save happy-dom`).
- The main JS chunk is over 500 kB (Vite warning only).
- Two agents edited this tree at the same time on 2026-11-04. All suites above were run on the combined final tree.
